# `apps/web` — the WordyMe front end

The React single-page app: the editor, the space and document tree, settings, and
everything else the user sees. It talks to `apps/backend` over the API and, in
production, is served by that same backend from the same origin.

## Stack

- **Vite** (Rolldown) — build tool and dev server
- **React 19** with **TypeScript**
- **TanStack Router** — type-safe, file-based routing (`src/routes`)
- **TanStack Query** — server state and caching (`src/queries`)
- **Zustand** — client state (`src/store`)
- **Tailwind CSS v4** — styling, with shared tokens from `@repo/ui`
- **Better Auth** — authentication, via the backend
- **Socket.io** — real-time updates
- **PWA** — installable, with an offline-capable service worker

The rich-text editor lives in `@repo/editor` (Lexical) and shared components in
`@repo/ui`; both are workspace packages, not part of this app.

## Running it

This app is not started on its own. From the repository root:

```bash
pnpm dev
```

That runs the backend and this app together, which is what you want — the dev
server proxies `/api`, `/storage` and `/socket.io` to the backend on port 3000,
so everything is same-origin exactly as it is in production.

Full setup instructions, including the backend environment and database
migrations, are in [LOCAL_SETUP.md](../../LOCAL_SETUP.md).

**This app needs no `.env` of its own.** `VITE_BACKEND_URL` is deliberately
empty so API calls stay relative; setting it is only necessary when the API
really is on another origin, and note that it is inlined at build time.

## Layout

```text
src/
├── routes/       # TanStack Router file-based routes (_authed, _unauthed)
├── components/   # App-specific components
├── queries/      # TanStack Query hooks
├── store/        # Zustand stores
├── providers/    # React context providers
├── utils/        # Helpers
└── main.tsx      # Entry point
```

`src/routeTree.gen.ts` is generated by the router plugin — do not edit it by
hand.
